# tool-inventory

導入済みのツール・仕組みを、記憶や勘ではなく固定の枠で棚卸しするためのスキル。目的は3つ。(1) 何が入っているかを可視化する、(2) それぞれが持ち込むリスクを明示する、(3) 「そもそも不要」なものを見つけて外す判断材料を作る。

「いくつか導入してきたが体系的にまとめていないので全て場当たり」という状態を解消するのが、このスキルの本丸です。

## いつ使うか

- ツール一覧を作りたい/更新したいと明示されたとき
- 新しいMCP・API連携・サードパーティツールを導入した直後(1行でも記録を足す)
- 定期的な見直し(月1回など)で、使っていないものを洗い出したいとき
- CLAUDE.md や環境が肥大化してきて、何が効いているか分からなくなったとき

## 手順

### 1. 対象を集める

まず棚卸しの対象を集める。以下を確認源にする(アクセスできるものだけでよい)。

- `~/.claude/` 配下(`agents/`, `skills/`, `hooks/`, `settings.json`, MCP設定)
- プロジェクトルートの `.claude/` と `CLAUDE.md`
- `.mcp.json` などのMCPサーバ定義
- ユーザーの記憶・口頭申告(自作のloop、外部SaaS連携、ブラウザ拡張など、ファイルに現れないもの)

ファイルにアクセスできる環境なら実際に読む。できない環境(チャットのみ)なら、ユーザーに「入れているものを箇条書きで挙げてください」と一度だけ促し、挙がったものを整理する。**推測で埋めない** — 分からないものは「未確認」と書く。

### 2. 6分類に振り分ける

各ツール・仕組みを、下の6分類のいずれかに置く。

| 分類 | 何を自動化するか | 例 |
|---|---|---|
| loop | 同じ作業を回す(作業自動化) | 毎朝のニュース収集、リンク切れチェック |
| skill | 判断基準を固定する(判断自動化) | 記事執筆ルール、返信トーン、frontend-design |
| agent | 専門担当を分ける(分業) | レビュー担当、調査担当、worker/advisor |
| goal | 成果まで束ねる(成果自動化) | 企画から公開前チェックまで一式 |
| hook | 強制実行と安全制御 | pre-commitでの機密ファイルブロック |
| MCP | 外部接続 | カレンダー、Drive、外部SaaS連携 |

**振り分けられないものには印をつける。** 「作業単位が大きすぎる(→ 小さく割る)」か「目的が不明確(→ そもそも要る?)」のどちらか。この印自体が次のアクションになる。

### 3. 4つの判断軸で評価する

分類できたものに、リスクの観点を足す。全部を毎回埋める必要はないが、書き込み権限を持つものと外部接続するものは必ず埋める。

1. **権限の範囲** — 何を読めるか/書けるか。読み取り専用か、書き込みもできるか。
2. **ブラスト半径** — 失敗したとき何が壊れるか。最悪ケースの被害範囲。
3. **保守リスク** — 公式/準公式/個人開発のどれか。放置されたら困るか。
4. **標準機能で代替可能か** — 同じことが素の機能でできないか。できるなら「不要」候補。

### 4. 表を出力する

以下の形式で必ず出力する。Markdownファイルとして保存し、ユーザーが継続更新できるようにする。

```markdown
# ツール棚卸し (最終更新: YYYY-MM-DD)

## 一覧

| 名称 | 6分類 | 権限範囲 | ブラスト半径 | 保守リスク | 標準機能で代替 | 判定 |
|---|---|---|---|---|---|---|
| (例) research-loop | loop | 読み取りのみ | なし(収集のみ) | 自作 | 不可 | 維持 |
| (例) 某SaaS連携 | MCP | 読み書き | データ改変あり | 個人開発 | 一部可 | 要検討 |

## 振り分け不能

| 名称 | 理由 | 次のアクション |
|---|---|---|
| (例) 全部いい感じにやるスクリプト | 作業単位が大きすぎる | goalに分解 or loopに縮小 |

## 外す候補(標準機能で代替可能 or 目的不明)

- (例) 某ツール — Xで代替可能。次回見直しで削除検討。
```

「判定」列は `維持 / 要検討 / 外す候補` の3つから選ぶ。

### 5. 外す判断を促す

「標準機能で代替可能」かつ「使っていない」ものが見つかったら、それを明示し、外すかどうかをユーザーに一度確認する。**勝手に削除はしない** — 提示までがスキルの仕事。

## 原則

- **推測で埋めない。** 分からないものは「未確認」と正直に書く。埋まっていない欄は、次に調べるべき場所の地図になる。
- **一度に完璧を目指さない。** まず10個だけ挙げて表にする。残りは後で足せばよい。
- **この表は使い捨てではない。** 保存し、`intro-log` で新規導入を記録するたびにこの表へ1行追記していく。棚卸しは「一度やる作業」ではなく「更新し続ける台帳」。
