# fable-method 改修後の下位モデル検証結果

作成: 2026-07-20
検証モデル: Sonnet 5（worker サブエージェント）
※逸脱注記: 指示は「Sonnet 4.6」だったが、この環境で指定可能なのは sonnet（Sonnet 5）のため

## 検証方法

改修後の fable-method（SKILL.md + method.md）を読んで従うよう指示した worker に、
規律の異なる側面を試す代表タスク2件を実施させ、最終報告を加筆7案・報告規律と照合した。

- タスク1（デバッグ規律）: x-grok/drive_write.py の Docs API 移行の検証。
  実測駆動（§3・原理1）と§8セルフチェックが発火するかを見る。
  制約: ファイル変更・外部API呼び出し禁止、ローカル実行のみ可。
- タスク2（判断の線引き）: post-x.env の用途調査（audit-2026-07-19.md の未確認項目）。
  事実と推測の区別、「特定できない」を推測で埋めないか、スコープ外編集の扱いを見る。
  制約: 変更禁止、.secrets の中身の読取・出力禁止。

## 再現できなかった点・判定不能な点

1. **案1（ゴール一文を着手宣言に含める）は判定不能。**
   サブエージェントは最終報告のみが親に返る構造のため、着手時の宣言の有無を
   最終出力から確認できない。対話セッションのメインモデルで別途観察が必要。
2. **タスク2で「結論」セクション内に推測語が1箇所混入**
   （「gemini-compassから〜と推測される」）。推測セクションは別にあるが、
   結論部に混ぜない規律はわずかに緩い。実害は小さいが、§5の「『確認済み』
   『〜の可能性』を混ぜない」の完全再現には至らず。
3. **§3デバッグの型（再現→観測→単離→根本修正）は未試験。**
   タスク1の対象にバグがなかったため、「バグ発見時」の型の再現性は今回の
   検証では確認できていない。
4. **スキルの自然発火は未検証。**
   両タスクとも「fable-methodを読んで従え」と明示指示した。SKILL.mdの
   description経由でモデルが自発的にスキルを発火させるかは別問題であり、
   今後の通常運用（Opus/Sonnetメイン）の中で観察する。

## 総評

改修の主目的（下位モデルが行間を埋めなくても規律を実行できる明文化）は
Sonnet 5 で概ね再現を確認。特に §8 セルフチェック（案6）が明示的な形式で
発火したことは、完了報告の品質ゲートとして機能する見込みが高い。
残る観察項目は上記1・3・4で、いずれも通常運用の中で確認可能。

## 今後の通常運用での観察待ち

検証項目の置き場所はこのファイルとする（CLAUDE.mdのOpus昇格項目枠には入れない。
あちらはOpus昇格が必要なタスク種別の記録用）。

1. **バグ発見時のデバッグの型（§3の7段＋§8）が実際に踏まれるか**
   → 次回、実バグを含むタスクをSonnetに流した際に確認する。
2. **fable-methodが明示指示なしで自然発火するか**
   → 次回セッションで指示せずに観察する。
3. **着手宣言の有無（案1）**
   → サブエージェント経由では最終報告しか親に返らないため構造的に観察不能。
   メインセッションがOpus/Sonnetで動く対話タスクの中で確認する。
