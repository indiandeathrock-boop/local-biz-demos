## frontend-design スキル運用ルール（local-biz-demos専用）

### 適用範囲
このルールは `local-biz-demos`（LBS量産パイプライン）にのみ適用する。VUHD関連のLP/UI作業には適用しない（VUHDは試行の場であり、本番品質の厳密適用は不要）。

### 背景
LBSのデモサイトは「テンプレ感のない一点物に見えるが、実際は量産可能」であることが事業の核心。`/mnt/skills/public/frontend-design/SKILL.md` はAIが作るUIがテンプレ化する3つの典型パターン（クリーム背景×セリフ×テラコッタ／黒背景×単色アクセント／新聞調レイアウト）を名指しで回避させ、ブリーフ固有の視覚選択を強制する。これを「1案件ごと」ではなく「業種カテゴリの追加・更新時」に適用することで、量産性と非テンプレ感を両立させる。

### 運用フロー

**1. 新規業種カテゴリのテンプレート作成・更新時（厳密適用）**

新しい業種カテゴリ（例：美容室、整骨院、工務店、飲食店など）のHTMLテンプレートを作成・大幅改修する際は、必ず以下を実施する。

1. 着手前に `/mnt/skills/public/frontend-design/SKILL.md` を読み込む
2. その業種の典型的な顧客・現場・素材・語彙を1つ具体的に固定してから設計する（「美容室」ではなく「郊外のファミリー向け美容室、客層は30-50代女性、価格訴求より安心感訴求」まで絞る）
3. SKILL.mdの2-Passプロセスに従い、トークンプラン（色4-6色をhex指定、タイプ2書体以上、レイアウト概念、signature要素）をまず提示する
4. そのプランがSKILL.md記載の3つの典型パターン（クリーム×セリフ×テラコッタ／黒×単色アクセント／新聞調）に寄っていないか自己批判し、修正点を明示してから実装に進む
5. コピー（見出し・CTA・空状態文言）もSKILL.md後半のUXライティング原則に従い、業種の実利用者視点・能動態で書く
6. 完成したトークンプラン（色hex値、書体名、signature要素の説明）を `local-biz-demos` 内に業種ごとの設計メモとして保存し、次回以降の参照・流用を可能にする

**2. 既存テンプレートへの変数置換による個別店舗デモ生成時（厳密適用しない）**

既存の業種テンプレートに店舗名・住所・写真などを変数置換するだけの通常運用では、上記2-Passプロセスは不要。テンプレート自体の質はステップ1で担保済みのため、ここはスピード優先で良い。

**3. 判断基準**

「これは新しい業種カテゴリの型を作る作業か、既存の型に変数を流し込む作業か」をまず自分で判定する。前者ならSKILL.mdを読んで2-Passを踏む。後者なら通常の変数置換フローで進める。迷ったら、テンプレートのHTML構造・CSS構造自体を変更するかどうかで判断する（変更するなら前者）。

### 品質floor（業種テンプレート作成時は必須）
- モバイル幅までのレスポンシブ対応
- キーボードフォーカスの視認性
- reduced motionへの配慮
- CSSセレクタの詳細度の衝突（`.section` と `.cta` など）がpadding/marginを打ち消していないか確認
